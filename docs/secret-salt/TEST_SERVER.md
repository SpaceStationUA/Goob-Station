## 0. Що потрібне до тесту

- **Окремий тестовий SS14-сервер**, не бойовий. Встановити на нього **гілку `feature/secret-salt-1.4-upstream-integration`** і сумісну клієнтську збірку; зафіксувати конкретний SHA.
- Адміністратор із правом керувати раундом (`AdminFlags.Round`) та доступом до серверних логів.
- Принаймні **2 тестові акаунти** гравців плюс адміністратор — для перевірки підсумків і захисту від дублів.
- **Приватний Discord-канал автора** з окремим тестовим вебхуком. Він не повинен бути загальним каналом станції.
- Налаштувати `secret_salt.author_discord_webhook` у **закритій серверній конфігурації / системі секретів**, доступній тільки адміністратору. У коді це `CVar.SERVERONLY | CVar.CONFIDENTIAL`; порожнє значення заборонить реальну доставку.
- **Увага: не використовувати `changecvar` для URL вебхука!** Його реалізація записує старе й нове значення CVar в адмінжурнал. Не вставляти адресу/токен у GitHub, чат, скриншоти, консольний лог або відкритий PR.
- Перед тестом повідомити учасникам, що **нікнейми й тексти відгуків** буде передано автору в приватний канал. Використовувати тестові, несекретні коментарі.

## 0А. Чи переживає приватний вебхук перезапуск

- `secret_salt.author_discord_webhook` має **порожнє значення за замовчуванням**. Сам код режиму **не зберігає** URL між процесами.
- Якщо адміністратор налаштував секрет у **постійному приватному конфігу**, захищеній змінній середовища або сховищі секретів, які знову підвантажуються при запуску, вебхук **залишиться доступним** після повного перезапуску.
- Якщо адресу задати лише тимчасово під час виконання сервера, після повного рестарту вона **може зникнути**. Сам по собі прапорець `CVar.CONFIDENTIAL` не гарантує збереження.
- Перед розгортанням перевірити, що під час оновлення сервера або пересоздання контейнера постійний конфіг/секрет **не видаляється**, а також що вебхук не було відкликано на стороні Discord.
- **Безпечно перевіряти факт налаштування, не показуючи сам URL:** після тестового раунду сервер не має писати попередження `mandatory private Discord webhook not configured`. Це не доводить успішну доставку; її треба окремо підтвердити в приватному каналі.
- `changecvar` НЕ використовувати для налаштування або читання цього секрету — реалізація команди може показати чи залогувати конфіденційне значення.
- **Два різні лічильники:** лічильник ротації Salt *навмисно* обнуляється після рестарту процесу. URL вебхука, навпаки, має надходити із зовнішнього постійного конфігу. Вони ніяк не залежать один від одного.

## 1. Перевірка одного повного раунду

1. Запустити сервер з **потрібною ревізією** гілки, переконатися, що клієнти можуть зайти.
2. У лобі перевірити видиму назву **«Секрет Сіль 1.4»**. У коді та YAML ідентифікатор лишається `SecretSalt`.
3. За потреби вибрати режим командою адміністратора:
   ```text
   setgamepreset SecretSalt
   ```
   Команда `setgamepreset` без другого аргументу налаштовує один раунд; **не** застосовувати до бойового сервера.
4. Запустити раунд (якщо сервер не стартує автоматично):
   ```text
   startround
   ```
5. Перевірити, що існують журнальні записи `ROUNDSTART ADDED`, `RULE STARTED` або `RULE SUMMARY`, `ROUND SUMMARY` у відповідні моменти, а розрахунки хаосу та ваги не мінялися.
6. Завершити тестовий раунд штатною адміністративною командою:
   ```text
   endround
   ```
7. **До перезапуску** дати гравцям час заповнити форму (максимум 60 секунд), перевірити, що вікно з'являється **після** табло раунду та що в ньому є попередження про передачу даних автору.
8. Дочекатися обох приватних звітів: технічний звіт після раунду й окремий звіт відгуків після завершення збору. Пов'язати їх за **однаковим номером раунду**.
9. Перевірити, що технічний звіт містить нікнейми та антагоністичні ролі **лише після завершення раунду**; звіт відгуків містить кількість, середню оцінку, до 3 найчастіших причин, нікнейми, оцінки, причини, коментарі.
10. Переконатися, що повідомлення **немає** в публічних каналах Discord і з `@everyone` / `@here` не виникають сповіщення. Не публікувати URL приватного вебхука в результатах.

## 3. Ротація

Послідовно зіграти два раунди `SecretSalt`; після кожного завершення перейти до лобі штатним способом або через адміністративне `restartroundnow` **після** завершення тесту відгуків. У лобі спробувати `setgamepreset SecretSalt` утретє. Очікується заміна на `Secret`, українське пояснення й відсутність `SecretSalt` у звичайному голосуванні. Після **фактичного запуску** іншого режиму `SecretSalt` знову доступний.

Повний перезапуск процесу сервера **за погодженим рішенням** скидає лічильник ротації. Окремої бази/файлу стану немає і не потрібно.

## 4. Звіт про проходження

Після виконання записати для кожного сценарію **PASS / FAIL / BLOCKED**, SHA збірки, дату, кількість тестових акаунтів, номер раунду й час очікування. Додати **відредаговані логи без паролів, вебхуків, ID акаунтів і приватних коментарів**, а також короткий опис виявлених проблем.

Якщо окремий тестовий сервер або вебхук ще не надані — позначати тест **BLOCKED**, не **PASS**. Автоматичний GitHub CI **не замінює** живий серверний тест.

**Після перевірки:** звернутися до автора перед будь-яким PR, злиттям чи розгортанням на основний сервер. Зміни ігрового балансу та обмежень антагоністичних ролей привидів заборонені без окремої згоди.
